# 代码镜子

[English](README.md) | 中文

左右对照看一个 git 仓库的改动，交给模型审查，把审查出来的问题标在对应的行上；每条问题可以分配出去，从发现、分配、修改到复查，整条工作链条都记下来。四个面板可以自由拖拽。

照着 VS Code 里 GitLens 的"审查更改"做的，是一个单独运行的小程序：一个本机服务加一个网页界面。

署名：JINGLEIW=FFAX　·　许可证：MIT

## 一、功能讲解

### 1. 看改动（镜子）

- **两种比较**
  - **两个分支比较**：比如 `main ⇄ feature/login`，看右边那一边相对左边改了什么（和 `git diff 左边...右边` 同一个算法，以两边分叉的地方为准），顶上显示"领先几次提交、落后几次提交"。
  - **还没提交的改动**：工作区相对最近一次提交的改动，包括新建的、还没加进 git 的文件。
- **改动的文件**：按文件夹收起来；每个文件标新增（A）、修改（M）、删除（D）、改名（R），带加减行数；可以搜文件名。文件少于 300 个时默认全部展开。
- **左右对照**：左边是原来的，右边是改过的，红色是删掉的，绿色是加上的；长行自动折行，没改的段落收起来。二进制文件、太大的文件（超过 1.5MB 的改动）、只改名没改内容的文件会直接说明，不硬画。

### 2. 审查差异

- 点"审查差异"审这次所有的改动，点"只审这个文件"只审当前文件。
- 审出来的问题按"关注点"分组，每条写明：文件、行号、严重程度（高 / 中 / 低）、问题、原因、怎么改。
- 问题直接显示在对照里出问题的那一行下面；点右边问题上的文件名，跳到那个文件、滚到那一行并闪一下。
- 一次审不完全部改动时（太多、太大），审了哪些、没审哪些、为什么没审，都列出来。
- 每次结果存在本机；下次打开同一组比较，会把最近一次结果带出来，标着审查时间。
- 模型连不上、没有这个模型时，直接说明，不编结果。

### 3. 工作链条

每条问题都可以交出去，记成一张工单（W1、W2……）：

| 交给 | 怎么做 |
|---|---|
| **Claude 去改** | 程序在你的仓库里调用 Claude Code 修这一条，改完自动复查 |
| **复制给别的 AI** | 把问题写成一段话复制到剪贴板，你贴给别的 AI；改好后点"改好了，去复查" |
| **我自己改** | 你自己改；改好后点"改好了，去复查" |

- 复查：把原来的问题和文件现在的全文交给审查方，问"这个问题还在不在"，结论是"复查通过"或"复查没过"，并写明原因。
- 每一步都记下时间、谁、做了什么：发现问题 → 分配 → 改完了（或没改动）→ 复查通过 / 没过 → 关掉。
- 状态：待分配、已分配、处理中、复查中、已解决、复查没过、没改动、出错了、中断了、已关闭。服务中途停过的话，正在跑的那一步记成"中断了"。

### 4. 面板自由拖拽

- 四个面板：改动的文件、左右对照、审查、工作链条。
- 按住面板顶上的标签，拖到哪里就放到哪里：上、下、左、右，或者叠成标签页；拖两个面板之间的缝改大小。
- 摆好的样子自动记住；顶上的"面板"能把关掉的面板找回来，"恢复默认布局"放回原样。

## 二、实现

### 整体结构

```
浏览器里的网页（React）
        │  只连本机 127.0.0.1:8795
        ▼
本机服务 server.mjs（Node，不装第三方包）
        ├── git ……………………… 算改动、取每个文件的改动
        ├── Claude Code 命令行 …… 审查、自动修改、复查（默认）
        └── 兼容 OpenAI 接口的模型服务 … 审查、复查（可选，比如本地 Ollama）
        │
        ▼
本机 data/ 文件夹：审查结果、工作链条（不上传）
```

### 看改动是怎么算的

| 要什么 | 用的 git 命令 |
|---|---|
| 每个文件加减多少行 | `git diff --numstat -z -M <比较范围>` |
| 每个文件是新增、修改、删除还是改名 | `git diff --name-status -z -M <比较范围>` |
| 没加进 git 的新文件 | `git ls-files --others --exclude-standard -z` |
| 领先、落后几次提交 | `git rev-list --left-right --count 左...右` |
| 一个文件的改动 | `git diff -M <比较范围> -- <文件>`；没加进 git 的新文件用 `git diff --no-index -- /dev/null <文件>` |

比较范围：两个分支比较时是 `左...右`，看没提交的改动时是 `HEAD`。网页拿到一个文件的改动以后，用 `@pierre/diffs` 的 `PatchDiff` 组件画成左右对照（`diffStyle: 'split'`），审查出来的问题用它的"行注释"（`lineAnnotations`）放到对应行下面。

### 审查是怎么做的

1. **挑要审的文件**：代码文件排前面，改得少的排前面；跳过二进制文件、依赖锁文件、整个被删掉的文件。一次最多送去 20 万字（接本地模型时 6 万字）的改动，最多翻 400 个文件；单个文件的改动超过一半额度就留着单独审。
2. **交给模型**
   - **Claude Code**：`claude -p … --output-format json --json-schema <结果格式> --system-prompt <审查要求> --tools "" --strict-mcp-config --setting-sources project --no-session-persistence --permission-prompts none`。改动从标准输入送进去，在临时文件夹里跑。关掉所有工具，不连外部服务，也不留会话，它只能看送过去的改动。结果从 `structured_output` 里取，格式由 `--json-schema` 保证。
   - **兼容 OpenAI 接口的服务**：调 `/v1/chat/completions`，要求只回一个 JSON，再从回答里取出来。
3. **整理结果**：严重程度只认高、中、低（别的记成"未标"）；核对问题说的文件是不是在这次审查的改动里；存成 `data/runs/<编号>.json`。

### 工作链条是怎么记的

- 每个仓库一份记录：`data/work/<仓库路径的指纹>.json`。里面是工单列表，每张工单记着问题本身、来自哪次审查、状态、交给谁、事件列表（时间、谁、做了什么、细节）。
- 同一个仓库的记录一次只让一处写，免得后台任务和网页请求互相覆盖。
- **Claude 去改**：在仓库文件夹里运行 `claude -p <问题和修改要求> --tools Read,Edit,Glob,Grep --permission-mode acceptEdits --permission-prompts none --strict-mcp-config --setting-sources project`，只给读和改文件的工具，不让它跑命令、不让它提交。改之前、改之后各算一次那个文件的指纹，用来判断它到底改没改。会话保留下来，会话编号记在链条里，可以追查。
- **复查**：把原来的问题和文件现在的全文（最多 15 万字）交给审查方，按 `{ fixed: true/false, reason: "原因" }` 的格式回答。
- 后台任务在网页上每 3 秒刷新一次；服务重启后，没跑完的任务记成"中断了"。

### 面板拖拽是怎么做的

用开源的 dockview（`dockview-react`，MIT）：四个面板注册成组件，`onReady` 时摆出默认布局。布局一变就用 `toJSON()` 存进浏览器本地，下次打开用 `fromJSON()` 摆回去。

### 本机服务的接口

| 方法 | 地址 | 做什么 |
|---|---|---|
| GET | `/api/config` | 默认仓库、审查方式 |
| GET | `/api/model` | 审查方能不能用 |
| GET | `/api/repo?path=` | 仓库的根目录、当前分支、分支列表 |
| GET | `/api/changes?path=&mode=&base=&head=` | 改动的文件列表和合计 |
| GET | `/api/patch?path=&mode=&base=&head=&file=` | 一个文件的改动 |
| POST | `/api/review` | 审查（全部或指定文件） |
| GET | `/api/runs?path=`、`/api/runs/<编号>` | 以前的审查结果 |
| GET | `/api/work?path=` | 工作链条 |
| POST | `/api/work/from-run` | 把审查出来的问题记成工单 |
| POST | `/api/work/<工单号>/assign`、`done`、`recheck`、`close` | 分配、说改好了、再复查、关掉 |

### 文件说明

| 文件 | 做什么 |
|---|---|
| `server.mjs` | 本机服务：git、审查、工作链条、接口、发网页 |
| `web/src/App.tsx` | 网页的主体：状态、顶栏、把各面板拼起来 |
| `web/src/Workspace.tsx` | 可拖拽的面板布局 |
| `web/src/FileTree.tsx` | 改动的文件 |
| `web/src/DiffPane.tsx` | 左右对照、行上的问题、跳到那一行 |
| `web/src/ReviewPane.tsx` | 审查结果、分配按钮、复制给代理 |
| `web/src/WorkPane.tsx` | 工作链条 |
| `web/src/api.ts` | 网页调用本机服务的接口和数据格式 |
| `web/src/styles.css` | 样式 |

## 三、怎么跑

要先装 Node 22 或更新的版本，还有 git。用 Claude Code 审查的话，还要装好 Claude Code 命令行并登录。

```bash
npm install
npm run build
npm start
```

然后在浏览器打开 http://127.0.0.1:8795 ，填仓库文件夹的完整路径，点"打开"。

### 设置（启动时用环境变量）

| 变量 | 意思 | 默认 |
|---|---|---|
| `MIRROR_ENGINE` | `claude` 或 `openai` | 有 `claude` 命令就用 `claude` |
| `MIRROR_CLAUDE_BIN` | `claude` 命令的位置 | 自动找（PATH、`~/.local/bin`） |
| `MIRROR_CLAUDE_MODEL` | 给 Claude Code 指定模型，比如 `sonnet` | 空，用账号默认的 |
| `MIRROR_MODEL_URL` | OpenAI 兼容服务地址（到 `/v1` 为止） | `http://127.0.0.1:11434/v1` |
| `MIRROR_MODEL` | OpenAI 兼容服务里的模型名 | `nemotron-3.5-bolt:e4b` |
| `MIRROR_MODEL_KEY` | 需要密钥的服务才填 | 空 |
| `MIRROR_REVIEW_BUDGET` | 一次最多送去多少字的改动 | Claude 200000，其他 60000 |
| `MIRROR_REPO` | 打开网页时默认的仓库 | 空 |
| `PORT` | 端口 | `8795` |

## 四、安全

- 服务只听本机 `127.0.0.1`，请求的 Host 不是本机就拒绝，别的电脑连不进来。
- 看改动、审查、复查都只读仓库。只有在一条问题上点了"Claude 去改"，Claude 才会改仓库里的文件，而且只能读和改文件，不能跑命令、不能提交，改完自动复查，过程记进工作链条。
- 调用 git 时不经过命令行解释器，文件名放在 `--` 后面；没加进 git 的新文件会先核对确实是这个仓库里的。
- 审查用 Claude Code 时，改动会发到 Anthropic 的服务器去审。不想让代码离开电脑，就改用本地模型（`MIRROR_ENGINE=openai`）。
